# 发布归档会话插件 0.3.10：绿色 CI 是真的发出去了，但 `npm view` 查不到

日期：2026-10-01
包：`@omdp/dsh-archived-sessions` 0.3.9 → **0.3.10**
触发：`git push origin master` + `git tag v0.3.10-archived-sessions`

## 背景

按 `docs/npm-publish.md` 的流程发布 `@omdp/dsh-archived-sessions@0.3.10`。
workflow `publish.yml` 在 push tag 时自动跑，本机无需 npm 登录（`npm whoami` 本机确实报
`ENEEDAUTH`，符合预期）。

## 结论：发布成功，但本机 `npm view` 会骗你

### 1. workflow 确实是绿的，而且这次真的发出去了

`gh run list` 显示 `v0.3.10-archived-sessions` → `completed success`，但**绿勾本身不是证据**
（本仓库历史上就吃过「绿勾但某包漏发」的亏，见 `publish.yml` 里的注释）。真正的证据在 run 日志里：

```
40.6831999Z ##[group]publish @omdp/dsh-archived-sessions@0.3.10
41.3758664Z npm notice 📦  @omdp/dsh-archived-sessions@0.3.10
41.3763439Z npm notice 30.6kB lib/client.js
41.3764314Z npm notice 34.3kB lib/index.js
41.3788527Z npm notice Publishing to https://registry.npmjs.org/ with tag latest and public access
43.2356396Z npm notice publish Signed provenance statement with source and build information from GitHub Actions
43.2358755Z npm notice publish Provenance statement published to transparency log: ...
44.9558755Z npm notice Your package is being processed and may take a few minutes to become available.
44.9563744Z + @omdp/dsh-archived-sessions@0.3.10          ← 这一行才是成功标志
```

同一 run 里另外三个包都走了「已发布 → skip」分支（`skip: @omdp/dsh-connector@0.3.8 is already published` 等），
说明**一次 tag 会遍历四个包，但只发新版本**，这正是想要的行为。

### 2. 🔴 但本机 `npm view` 连续 8 次报 E404（约 3 分钟）

```
$ npm view '@omdp/dsh-archived-sessions@0.3.10' version
npm error code E404
npm error 404 No match found for version 0.3.10
```

**这是本地 packument 缓存，不是发布失败。** 直连 registry API 立刻拿到正确结果：

```sh
curl -s https://registry.npmjs.org/@omdp%2Fdsh-archived-sessions
```

```jsonc
{
  "dist-tags": { "latest": "0.3.10" },
  "versions": ["0.3.0", ..., "0.3.9", "0.3.10"],     // 0.3.10 在
  "time": { "0.3.10": "2026-10-01T08:41:54.000Z" }   // 发布时刻
}
```

时间线对得上：CI 上传 `08:38:44` → registry 记录 `08:41:54`（暂存处理约 3 分钟）→
而本机 `npm view` 在 `08:39`~`08:42` 之间一直读缓存报 404。

**教训**：判定「发出去了没有」以 **registry API** 为准；
`npm view` 只是辅助，遇到 404 **先怀疑缓存**，不要急着重发（重发会撞
`E409 Cannot publish over previously staged version`）。

### 3. registry 的 integrity 可以和本地 tarball 对上

发布前在本地 `npm pack` 拿到

```
shasum: 71c747affb09551bb1f849f4cc3712b8a7b7e635
integrity: sha512-/heFSwtRrsFV5[...]AEs9VvYI7mEdw==
```

registry 返回的 `dist.integrity` 与之一致 ⇒ **确认线上那份就是我验证过的那份 tarball**，
而不是「某个别的构建产物」。

## 可复用要点

### 4. `npm pack` 产物必须逐条核对（本仓库 0.3.0 就翻过车）

0.3.0 的 tarball **只有 4 个文件、没有 `lib/`**——仓库 `.gitignore` 的 `**/lib/` 规则把源码目录
整个忽略了，CI checkout 里没有源码，装出来的插件直接加载失败。

所以发布前跑一次 `npm pack` 并核对清单（本次实际结果）：

```
package/LICENSE             1.1kB
package/README.md          35.8kB
package/cordis.patch.yml    330B
package/lib/client.js      30.6kB
package/lib/index.js       34.3kB
package/package.json        1.3kB
total files: 6
```

顺带从解包后的 `package.json` 复核**将要发布的内容**（而不是仓库工作区里的）：
`version=0.3.10`、`peerDependencies["@deepseek-ai/dsh"]=">=0.2.0-rc.1 <0.2.1-0"`、
`dsh.client.inject` 已去掉不存在的 `@deepseek-ai/dsh-client-runtime`。

### 5. 用 `gh` 抓日志时的两个坑

- `gh run view <id> --log` 输出很长，工具侧会被截断 ⇒ **先 `Out-File` 存盘再读**，
  并用 `Select-String` 定位片段（本次用 `group\]publish @omdp/dsh-archived-sessions` 定位）。
- 日志里带 ANSI 颜色码，匹配前先 `-replace '\x1b\[[0-9;]*m',''`。
- PowerShell `-f` 格式化遇到 `[bool]` 参数会报 `Index (zero based) must be greater than
  or equal to zero` ⇒ 改用字符串拼接（`"  x = " + [bool]$v`）。

### 6. tag 命名与「一次只推一个」

沿用仓库约定 **`v<version>-<plugin>`**（本次 `v0.3.10-archived-sessions`）。
`on: push: tags: v*` 是**每个 tag 一个 run**，而每个 run 都会遍历全部四个包去 publish
⇒ 同时推多个 tag 会让多个 run 抢同一批版本，撞 `E409`/`E403`，且**每个 run 里都有包侥幸成功**
⇒ 「看起来都成功、实际各漏一部分」。所以**一次只推一个 tag**。

### 7. 发布后本机的更新（用户侧）

用户自己更新 profile 钉版并重启 DSH，不要代为操作：

```sh
cd ~/.dsh/profiles/<name>
pnpm update @omdp/dsh-archived-sessions
```

`readInstalledVersion` 读的是 `node_modules`，所以**只改 `package.json` 钉版而不
`pnpm install`** 的话，市场页仍会显示「可更新」——必须真正装下去再重启 DSH。
